## Description

dl-012 R3 by adr-003 D6–D7, option A of the spike (RP3-17 A1, A2): a page whose session the
console no longer recognises — the console was restarted — recovers **in place** once the browser
holds a session again, instead of staying lost for good.

- A tab whose token exchange succeeds (`POST /api/session` 204) posts a message **with no
  content** on the same-origin `BroadcastChannel` `wfui-session`.
- A lost page, on that message or when it becomes visible again — at most once per focus, one
  probe at a time, with the 10 s timeout of `watchFragmentToken` — asks `GET /api/server` with its
  cookie only; an OK answer reloads the page on its own address (path and query), a 401 leaves the
  notice.
- No token, session id or path crosses tabs or reaches a file, a link or a log; nothing is added
  to the URL (no `next=`, no redirect); a failed token exchange stays final (bug-016's rule, W3-7):
  recovery is a probe with the cookie, never a retried exchange.
- The notice tells the user what to do (catalogue `shell.session.lost.body`, adr-003 D6).
- Deep links across restarts are promised **with `--port` only** (D7): a console on another port
  is another origin.
