## Summary

Scenario M-02.2 "Group unknown states in generic buckets: To approve" (`test/e2e/memory-list.spec.ts:229`) failed once on Firefox: the click on the state bucket link did not navigate, so the link never became the current page.

## Steps to Reproduce

1. `gates.yml` `workflow_dispatch` with `scope=task` on a branch whose own specs include `test/e2e/memory-list.spec.ts` (run 45414655791, task-093, SHA `a4aa6e8b`).
2. The `own-specs (firefox)` job runs M-02.2 for the bucket *To approve*: `openList`, then `bucketLink(page, 'To approve').click()`.
3. The test expects the link's `aria-current` to be `page`.

## Expected Behavior

The click navigates to `/p/<pid>/memory?bucket=toApprove` and the bucket link carries `aria-current="page"`.

## Actual Behavior

Attempt 1 of run 45414655791: `expect(locator).toHaveAttribute('aria-current', 'page')` failed after 5000 ms, `unexpected value "null"`; the locator `getByRole('list', { name: 'States' }).getByRole('link', { name: /^To approve \d+ / })` resolved 13 times to `<a class="filter-link" href="/p/<pid>/memory?bucket=toApprove">`; the trace's network log shows only `/memory`, no `?bucket=` request. 1 failed, 58 passed. The rerun (attempt 2, 59 passed) and the Wave 1 gate's `scope=wave` run 45436485768 (Firefox shards 1 and 2) passed.

## Evidence

The Playwright report artifact `playwright-report-own-firefox` of run 45414655791 attempt 1 (error context and trace of the test).
