## Summary

The repository state fingerprint follows a symbolic link that stands for a folder of the project:
when `.wingfoil` is replaced by a link, it reads and hashes the files behind the link, outside the
project. spec-001 §4.4 says a link is never followed.

## Steps to Reproduce

1. A project the console shows, with `.wingfoil/` tracked.
2. In the working tree, replace `.wingfoil` with a symbolic link to a folder outside the project
   that holds a `memory.yaml` (git then lists every tracked file under `.wingfoil/` as deleted).
3. Edit the `memory.yaml` outside the project and wait for the watcher's check.

## Expected Behavior

An entry whose path goes through a link inside the repository is marked by the link, without any
read behind it; an edit outside the project does not move the state key.

## Actual Behavior

The `Fingerprinter` (`server/src/snapshot/fingerprint.ts`) `lstat`s and reads
`.wingfoil/memory.yaml` and `.wingfoil/ui.yaml` through the link (the trace shows `openat` of both
without `O_NOFOLLOW`), and an edit of the outside `memory.yaml` moves the fingerprint. Only the
final path component is checked for a link. The content is hashed, never kept or exposed.
