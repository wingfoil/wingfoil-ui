## Summary

On WingFoil 0.2.2, one Memory file whose frontmatter is not valid YAML makes `memory search` exit
with code 2. The console's adapter reads exit 2 as its own defect, so every read behind `memory
search` (the Memory list, an element, Today, the history) would answer 500 `internal`: one file
hides the whole project, as bug-024 by another path.

## Steps to Reproduce

1. A project on WingFoil 0.2.2 with a Memory file whose frontmatter holds `id: [unclosed`.
2. `npm run -s wingfoil -- memory search --format json` in it (or `GET /api/p/:pid/elements`).

## Expected Behavior

The valid elements are listed and the broken file becomes one project warning, as WingFoil 0.3.1
does (`W_MEMORY_UNREADABLE`) and as bug-024's fix does for a file without frontmatter.

## Actual Behavior

0.2.2 exits 2 with `{"error":"missed comma between flow collection entries (2:1) …"}`; the adapter
(`server/src/cli/adapter.ts`) maps exit 2 to a defect of the adapter, so the read would answer 500
`internal`.
