## Summary

The test suites rely on each test to keep the console away from the user's own state directory
(`~/.config/wingfoil-ui` on Linux): a test that starts the console in its own process without
`WINGFOIL_UI_STATE_DIR` or the harness environment resolves the real directory and, since the
console writes its address file at every start (task-058), writes there.

## Steps to Reproduce

1. On task-058's branch before its fix `321ab4bb`: `test/server/main.test.ts` calls `main()` with
   the process environment, with no `WINGFOIL_UI_STATE_DIR`.
2. `npm run test:coverage`.

## Expected Behavior

No test can read or write the state directory of the user who runs the suite: the default suites
resolve the state directory inside the run's temporary root unless a test sets another one on
purpose.

## Actual Behavior

The first `test:coverage` of task-058 (2026-11-05) wrote `consoles/33511.json` (a dead pid) into
the user's real state directory; its developer removed it and the folder, `state.json` untouched.
`main.test.ts` was fixed in task-058 (`321ab4bb`, `vi.stubEnv`), and its review found no other
start that reaches the directory (`runLauncher` passes `stateDir`; bin spawns get `harnessEnv`,
which moves `HOME`, `XDG_*` and `APPDATA` into the test root; the e2e, smoke and timing suites set
`WINGFOIL_UI_STATE_DIR`). The protection is per test: Vitest's global setup
(`test/global-setup.ts`) sets no state directory.

## Evidence

- task-058's Execution Notes, `### red / green / refactor` (the incident) and its review round 1
  (the isolation check of every suite).
- `server/src/state/location.ts` `resolveStateDir`: `WINGFOIL_UI_STATE_DIR`, then
  `$XDG_CONFIG_HOME/wingfoil-ui`, then `~/.config/wingfoil-ui`.

## Notes

Found by task-058 (2026-11-05); opened on the approver's OK ("vitest: a", 2026-11-05), to be
absorbed into task-058. Fix direction: the Vitest setup sets `WINGFOIL_UI_STATE_DIR` (and the
variables the resolution reads) inside the run's temporary root for every test, a test that needs
the resolution without it unsets it explicitly, and a guard test fails when the state directory a
test resolves lies outside the temporary root.
