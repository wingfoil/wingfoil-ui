## Summary

A request for a build asset whose name is too long for the file system answers **403** with the
error body code `invalid-request`: the status and the code disagree, and neither says "not found".

## Steps to Reproduce

1. A console with a web build (`npx wingfoil-ui` from a checkout after `npm run build`, or the
   packed app).
2. `GET /assets/` followed by 256 `x` characters, with the session.

## Expected Behavior

As for every other missing path under `/assets/` (`server/src/http/app.ts`, the not-found handler:
"a missing build asset stays a 404"): 404 with the body code `not-found`.

## Actual Behavior

403 with `{"error":{"code":"invalid-request","message":"Invalid request"}}`. The static file
plugin (`@fastify/static`) answers a name the file system refuses as too long with 403, and the
console's error handler (`server/src/http/app.ts`, `setErrorHandler`) keeps the status of every
4xx client error and writes `invalid-request` for all of them. No data is exposed: the path holds
only the build's static files.
