## Summary

Two tests of `test/server/http/project-routes.test.ts` (the history route, task-048) time out at
their default 30 s budget in `npm run test:coverage` when the machine is loaded, although the
behaviour is right.

## Steps to Reproduce

1. A loaded machine (1-minute load 13–20 on 12 cores, other worktrees running their gates).
2. `npm run test:coverage` through the machine-free slot.

## Expected Behavior

The default suite is load-independent (bug-004, task-026; the rule bug-023 applied): each test's
budget covers its own work under load.

## Actual Behavior

`Error: Test timed out in 30000ms.` on:

- "GET /api/p/:pid/elements/:eid and /history > answers the history of a plan closed by hand and of
  a parked and an amended element, contract fields only" (line 488) — in task-049's first
  `test:coverage` run (2026-11-04, slot granted at load 9.71, the load rising to 16–20 during the
  run) and in task-052's first run (slot granted at load 13.36);
- "… > lists the 0.3 operations but assign in the Memory events" (line 528) — in task-049's first
  run.

Neither task changed server code. The file passes alone (42/42, task-049 at load 11–15; task-052
in the slot), and both tasks' second full runs passed.

## Evidence

The Execution Notes of task-049 and task-052 (gates, first `test:coverage` run, load and slot
wait per run).

## Notes

Found during Sprint 1 Wave 0 of `minor-v0.3`; opened on the approver's OK (2026-11-04). Same class
as bug-004 and bug-023: one test body builds fixtures and runs several CLI history reads in one
30 s budget. Candidate fix: size the tests' budgets for their own work by the `test/harness/load.ts`
rule, or split them.
