## Rationale

- Hosted runners take the load off the machine the approver and the console share, and each
  task's gates no longer wait for one another; Wave 1 lost about a day to a waiter ended by a
  cleanup. A public repository runs them at no cost.
- A run per push with `cancel-in-progress` gives one result per branch tip; the push is also
  where the public-text check already applies.
- `test:timing` stays local because its budgets were measured on this machine (dl-009); a runner's
  numbers would move them.
- Running the wave scope on the phase branch's tip, before the merge, keeps `main` unpushed until
  the gate is green, and the tree is the same as the merge's while `main` receives only the wave
  merges (checked by the empty diff).
- The `definition-of-done` wording "where `gates.yml` exists on the branch" is true before and
  after the governance task's merge, so the directive needs no second change.
- Trade-offs: a gate now needs a push, so a branch's history is public sooner (the public-text
  check guards it); the CI and the local machine can differ (git version, fonts, timing) — dl-011's
  strict-identity recipe and the wave dispatch already cover the known classes; a run lost to
  GitHub's availability is re-run, or the gate falls back to the slot with the approver told.
