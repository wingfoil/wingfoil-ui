## Rationale

- **The runner keeps every gate the approver's.** It finalizes only the step it launched, launches
  only what `launch.allow` lists, and its agents are refused `memory approve` by the CLI (W-39); the
  orchestration by hand cost a session per stage (RP3-13).
- **H1, H2 and M2 block.** H1 lets code an agent planted run as the approver at the moment of a ruling,
  past the CLI's refusal of the agent's identity; H2 lets an agent widen its own sandbox or take the
  approver's address for later launches; M2 lets an agent forge the scope OK or the final OK that
  Decision 5 makes a ruling. None is the accepted risk of Decision 9.
- **The pin moves here, not at v0.3.1's planning,** because under Decision 3 the runner itself runs
  that planning and cannot start on 0.3.1 (the approver's ruling of 2026-11-19). Trade-off: a governance run changes product files (the
  matrix, its samples and tests, the package README's matrix line, `CHANGELOG.md` *Unreleased*); the
  supported range stays 0.2.2 to 0.3.x.
- **CI by decision first.** A bound check runs outside any sandbox from the agent-writable clone (H2);
  one extra review launch per task is the cost until the fixed release.
