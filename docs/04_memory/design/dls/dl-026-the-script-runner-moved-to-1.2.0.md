## Decision

1. **Move the runner to `runner-1.2.0`**: its seven changed common files copied unchanged, checked
   by `manifest.mjs --check` and `--digest` against the sha256 above. The DNA, the adapters, and the
   Memory, workflow and role models stay as they are.
2. **`config/runner.yaml`:** `Bash(npx tsc:*)` and `Bash(node --test:*)` leave `permissions.extra`;
   every other key stays (`push: false`, `launch.manual: []`, no `container`, no `live_checks`).
3. **Tests through `npm run`:** `definition-of-done`, `CLAUDE.md` and `test/README.md` say `npm test
   -- <files>` for the targeted runs and the public-text check, the same `vitest run <files>`.
4. **Review findings:** `definition-of-done` › *review* — a finding inside the task's own change is
   recorded in the `memory park --reason`, no bug; a bug only for a defect outside it.
5. **`wingfoil-cli` › *The script runner*:** rule 10 — `launch.manual` may name a step now (its
   notice reads with `--read`), empty while none of ours is manual; rule 12 — the CI hand-off is the
   approver's command from the runner home, never `push: true` or a `live_checks` entry that pushes;
   rule 14 — the approver reads a line's workflow or Memory only with `run.mjs --line trunk --read
   <verb>`, and never pastes a notice command whose element or instance id is not plain (R-1); rule
   15 — container mode is never used on this machine (C-1, C-2).
6. **Where:** on `main` and on `design/dev-loop_v0.3.1`; the approver fast-forwards the runner home
   with no step in progress, and `task-091` continues on 1.2.0.

## Rationale

- The weekly budget counts what the agents really spend, subagents included.
- The approver never runs a line clone's CLI: `--read` closes the last place a notice sent them there.
- One way to run a targeted test, in and out of the runner: the agent's prompt and the directive
  no longer disagree.
- The CI push stays a human action on a branch the approver has reviewed; nothing in the runner's
  configuration pushes or approves.
