## Context

`minor-v0.3` shows a project's state from its Memory (`release-planning-rel-v0.3-plan`, RP3-7,
RP3-8: `features: [T2, T5, M2, R5, C1]`): the **progress card** on Today (T2 — US-T-12 … US-T-15,
TT-STATE-08), **recent activity** (T5 — US-T-08), the **missing-references** filter and badge of
the Memory list (M2 — US-M-03, US-M-04) and the **traceability** page (R5 — US-R-01). Their
conventions are the project's `.wingfoil/ui.yaml` (C1, spec-005): spec-005 §4 defines what a
reference is and how every figure is computed, §4a the held gates; spec-003 gives each element its
kind, tone and actor. spec-004 §3 lists `GET /api/p/:pid/progress` ("progress card figures",
v0.3) without a body, and has no traceability route; spec-005 §2 leaves the shape of the
`ui.yaml` warning — on `/config` and with the progress figures — to this spec (RP3-14, step 5c).

Without one definition the four views would each re-read every element file, re-derive
references and done states in the web (against spec-003 §8: "`web/` renders it and never
re-derives it") and drift on the fixture's figures (`02_bdd/00_conventions.md` *Preset variant*:
project completion 25 %, tasks 1/4, open bugs 1, pending gates 3, coverage 3/5). The screen is
`ux-reference.md` §4.1 (v0.3) and §4.8 (v0.3, the N8 study); this spec fixes the server side: the
reference index, the routes' bodies, the missing-reference flag, caching, cost and safety.

What exists today: no `ui.yaml` loading, progress or reference code in `server/src` (a search for
`progress`, `traceab` and `ui.yaml` finds only the `in-progress` bucket, git's
operation-in-progress markers and a comment of `server/src/git/git.ts` naming the future preset
commit); the snapshot memoises
each read per content key, an element file per path (`server/src/snapshot/snapshot.ts`, header
and `element()`), and an element file is read only one at a time, for the element read
(`server/src/reads/element.ts`, `server/src/http/project-routes.ts` `element`).

## Specification

### 1. The reference index

One index per repository state, shared by every consumer: the progress figures (§3), the
traceability route (§4), the missing-reference flag (§5) and the hold `when-references-done` of
the descriptor (spec-005 §4a, spec-003 §3).

**Inputs** — no new CLI command:

| Input | Source |
|-------|--------|
| the non-archived elements (`id`, `type`, `title`, `status`, `path`) | the cached `memory search` (spec-001 §3) |
| each element's frontmatter | the direct read of spec-001 §4.2, at the `path` `memory search` returned, consistency-checked (`id`, `type`, `status`); the index keeps the frontmatter **values** of §1 only — never the body, which only the element read keeps (spec-001 §4.2, the bulk consumer) |
| the types' states | `.wingfoil/memory.yaml` (spec-001 §4.1) |
| categories, patterns, `requires`, `progress`, `holds` | the effective `ui.yaml` (spec-005 §2–§3) |
| kinds, tones, actors, holds | the descriptor (spec-003 §8), computed with the same index |

**Values.** For each element, the values of its **top-level** frontmatter fields other than `id`,
`type`, `title`, `status`, `tags` and `rejection_reason` (spec-005 §4): a field whose value is a
string, and every string item of a field whose value is a list. Nested maps and the items of
nested lists are not read; numbers, booleans, dates and `null` are not values (YAML `release: 0.3`
is a number). A value is taken **as written** — no trimming, no case folding, no prefix grouping.
One element carrying a value twice (two fields, or a list repeating it) is linked once.
**At most 200 values per element** are kept, in field order then list order; an element with more
is indexed on its first 200 and named in the route's `capped` list, as `unreadable` names an
unreadable file (§3–§5): a figure or a flag that involves it may be incomplete, and the page says
so.

**References** (spec-005 §4, in this order, the first that applies):

1. the value equals the id of **another non-archived** element (not the element's own id) →
   an *element reference*, category = the category of that element's type (spec-005 §2–§3); a
   type with no category gives no category;
2. the value is at most 256 characters long (measured as written, before the escape of §9),
   holds no line break (LF or CR) and matches a `taxonomy.patterns[].match` (the first entry that
   matches, in file order) → a *pattern reference*, category = that entry's;
3. otherwise the value is not a reference.

Rule 1 compares **full** ids only: a value holding a short id (`task-046`, spec-011 §1) equals no
full id and is not an element reference (rule 2 may still apply); WingFoil 0.3.2 accepts short
references in its Memory verbs (spec-011 §1), a neighbour a later release may follow.

A value equal to the id of an **archived** element is not an element reference in v0.3: the
archived elements are not listed by `memory search` and are read only lazily (spec-001 §3) —
rule 2 may still apply (TQ-3 (a), decided by the approver 2026-11-03; `ux-reference.md` §4.8). A
reference **with no category** links its element but enters no figure, no traceability row and no
`requires` check ("No category — not counted in progress figures", spec-005 §2).

**Done** = descriptor kind `last`; archived elements are in no figure (spec-005 §4).

**In scope** of the current element `C` (spec-005 §4): an element one of whose values (above)
equals `C.id` or `C`'s `version` field when it is a string — e.g. a task's `release: v0.1` and
`minor-v0.1` with `version: v0.1`; `C` itself is not in its own scope. With no current element, every element is in
scope.

**Unreadable files.** An element whose file fails the direct read (spec-004 §5 `read-error`
kinds `outside`, `missing`, `shape`, `mismatch`) has no values: it links nothing, is in no scope,
is left out of coverage and of the missing-reference flag, and is named in the route's
`unreadable` list (§3–§5). Its `memory search` entry still counts where only the list and the
kinds are needed (iterated when no scope applies, open defects, pending gates). A list never fails
for one file (spec-004 §5).

**Cost.** The index reads each non-archived element file with bounded concurrency (at most 16
reads at a time), on the first request of a state that needs it, and only the files whose content
changed since the last index (§8, reuse). It is needed by `/progress` and `/traceability`, by
`/elements` when `taxonomy.requires` names a type (§5), and by **every descriptor computation**
when the effective `holds` has a `when-references-done` entry (spec-005 §4a) — so with the
sw-life-cycle preset (its `release-line` hold, spec-005 §5) it is built for Today and `/elements`
on every state. A request that needs no value (e.g. `/elements` with no `requires` and no such
hold) does not build it. No CLI process is started per element (REQ-PERF-05, its technical task
TT-PERF-05): the processes stay those of
`memory search`, `dna show` and the version check, and the Memory events are one `git log`
(spec-002 §3), all already cached per state.

### 2. The effective configuration and its warning (spec-005 §2)

`contracts/api/ui-config.schema.json` (new) holds the `ui` section of `GET /api/p/:pid/config`
and the definition `status`, referenced by §3 and §4:

```
status = { source: "file" | "none" | "ignored",
           warning?: { code: "ui-config-ignored", failure } }    # present when source = "ignored"
ui = { status,
       taxonomy: { categories: [{ type, category | null, origin }],      # one per declared type
                   patterns:   { value: [{ match, category }], origin },
                   requires:   { value: [{ type, categories }], origin } },
       progress: { mode: { value, origin }, scope: { value: { type } | null, origin,
                                                      current: ElementRef | null },  # origin of current: "derived"
                   phases: { value, origin }, iterates: { value | null, origin },
                   defects: { value | null, origin } },
       holds: { value: [{ type, state, approve }], origin },
       artifacts: { value: [{ path, phase }], origin } }
origin = "declared" | "inferred" | "derived"
```

- `source`: `file` — a valid file; `none` — no entry at `.wingfoil/ui.yaml`; `ignored` — an
  entry that is not used (not a regular file, above 64 KiB, not YAML, an alias or a duplicate key,
  the schema or a semantic check failed; spec-005 §1–§2). With `none` and `ignored` every value is
  `inferred`.
- `failure` is the text after "ui.yaml ignored: " in spec-005 §2 ("progress.mode must be sequence
  or flow (found spiral)", "not a regular file", the YAML engine's message with its line for
  C-04.2), passed through the sanitiser of tool messages (`server/src/git/redact.ts`
  `redactLocalPaths`: local folders redacted, controls escaped, capped) — it quotes the file's
  content. The web renders "ui.yaml ignored: {failure}" from its catalogue (spec-008).
- `ElementRef = { id, shortId?, title, type, status, tone }` — `shortId` as spec-011 §1, `tone` as
  spec-003 §7.
- `config.schema.json` gains the property `ui` (`$ref` `ui-config.schema.json`), absent when
  `memory.yaml` cannot be read (the semantic checks need it; `types` then carries the error).

### 3. `GET /api/p/:pid/progress` (T2)

`contracts/api/progress.schema.json` (new). No query parameter (any → 400 `invalid-request`).

```
{ ui: status,                                          # §2: the warning Today shows (C-04.1)
  mode: "sequence" | "flow",
  scope: { type: string | null,                         # progress.scope.type in sequence mode, else null
           current: ElementRef | null,                  # the derived current element (spec-005 §4)
           basis: "derived" | null },                   # "derived" when current is set (v0.4 adds "workflow-status")
  figures: {
    completion:      Shown<{ value, percent, references: [{ id, done, total, percent }],
                             referencesCount, ids }> | Unavailable<"no-reference-categories" | "no-linked-elements">,
    phase:           ReadOnly,
    phaseCompletion: ReadOnly,
    iterated:        Shown<{ type, done, total, ids, doneIds }> | Unavailable<"no-iterates-type">,
    openDefects:     Shown<{ type, count, ids }> | Unavailable<"no-defects-type">,
    pendingGates:    Shown<{ count, ids }> },
  unreadable: [id], capped: [id] }                      # §1: files not read / indexed on 200 values
Shown<T> = { state: "shown" } & T
Unavailable<C> = { state: "unavailable", reason: { code: C } }
ReadOnly = { state: "read-only", reason: <the reason of capability workflow-position> }
```

- **Scope** (spec-005 §4, RP3-14 D2): in `sequence` mode with `progress.scope`, `current` is the
  0.2.2 derivation on every WingFoil version; `null` with `scope.type` set renders "No current
  <type>" and project-wide figures (T-12.5); `flow` mode or no `scope` → `type: null`,
  `current: null`, rendered "Whole project" (T-12.2, C-04.1).
- **completion** — spec-005 §4 project completion over the elements in scope: `references` are
  the `requirement` and `feature` references with ≥ 1 linked element in scope, each with its
  in-scope `done`/`total`; `value` their unweighted mean (0 … 1), `percent` =
  `round(100 × value)` (half up), each reference's `percent` the same rule on `done/total`.
  `references` holds at most 10 entries in natural id order (digit runs compared as numbers),
  `referencesCount` the number of contributing references — the explanation of T-14.1 ("Mean of
  reference completion over 2 references with at least 1 linked element: US-M-01 50 %, US-S-01
  0 %", then "and <n> more" past 10). `ids` = the in-scope linked elements of every contributing
  reference. Unavailable: `no-reference-categories` when no effective category is `requirement`
  or `feature` (no such pattern entry, no type so categorised) — "Completion needs references —
  see Configuration › Taxonomy" (T-12.2); `no-linked-elements` when there are such categories but
  no reference has a linked element in scope — "No references linked in <scope>".
- **phase**, **phaseCompletion** — always `read-only` in v0.3, with the reason the project
  header gives the capability `workflow-position` (`GET /api/p/:pid`, `project.schema.json`
  `capabilities`): `needs-version {minVersion}` below 0.3.0 ("Phase — needs WingFoil 0.3 (this
  project: 0.2.2)", T-15.1; "Phase completion — needs WingFoil 0.3", T-15.2), `not-in-release`
  from 0.3.0 (spec-001 §6), `unsupported-version {range}` outside the range. No phase strip and
  no `flow` columns in v0.3: both need `workflow status` (spec-005 §1 `phases`, v0.4).
- **iterated** — `progress.iterates` (declared or inferred, spec-005 §3): `ids` its in-scope
  elements, `doneIds` the done ones, `done`/`total` their counts ("Tasks 1/4", T-12.1; T-13.2
  lists the 4 with `task-002-memory-list` done). Unavailable when no type is set.
- **openDefects** — `progress.defects` elements not done, project-wide ("Open bugs 1").
  Unavailable when no type is set (the figure is not shown).
- **pendingGates** — project-wide, elements of descriptor kind `gate` without `approveHeld`
  (spec-005 §4, §4a; `gate-waiting` excluded): "Pending gates 3" (T-12.1, T-13.1).
- **Figure filters on the Memory list (US-T-13).** Each shown figure is selectable; it opens
  `/p/<pid>/memory?figure=<code>`, `code` ∈ `completion`, `iterated`, `open-defects`,
  `pending-gates`. The Memory list shows the elements whose full id is in that figure's `ids` in
  the current `/progress` answer (the query Today shares), its other filters cleared, the active
  filter named by the figure's label ("Pending gates", T-13.1) with a control that clears it; an
  unknown `code`, or a figure not `shown`, shows the list unfiltered with no active filter. The
  ids are never placed in the address (TQ-4 (a), decided by the approver 2026-11-03).
- No input of this route is the DNA or the Memory events: a failed `dna show` or events read
  does not fail it (the descriptor's kinds and holds do not need them, spec-003 §2, §3).
- `ElementRef.title` and every pattern reference id are escaped (§9).

### 4. `GET /api/p/:pid/traceability?scope=` (R5)

A new route (spec-004 §3, v0.3); `contracts/api/traceability.schema.json` (new). `scope` ∈
`current` (default) | `project`; any other value or parameter → 400 `invalid-request` (the query
schema; an unknown `:pid` → 404 first).

```
{ ui: status,
  patterns: boolean,                    # the effective taxonomy.patterns is non-empty (selects R-01.4's text)
  scope: { type: string | null, current: ElementRef | null, applied: "current" | "project" },
  figures: { completion: <as §3, over the applied scope>,
             phaseCompletion: ReadOnly,
             coverage: Shown<{ carrying, total, percent }> | Unavailable<"no-requires">,
             referencesWithoutElements: integer },
  references: [{ id, category, element: boolean,  # element: the id is a listed element's (then in elements[])
                 linked: [id], done, total, percent | null,
                 status: "completed" | "in-progress" | "not-started" | "no-elements" }],
  missing: [{ id, categories: [category] }],
  elements: [Row & { done: boolean, inScope: boolean }],
  unreadable: [id], capped: [id],
  eventsError? }
Row = the item of elements.schema.json (`/elements`: id, shortId, title, type, status, tags,
      path, localChanges, descriptor) — one entry per element named anywhere in the answer
```

- **scope** — `applied` is `current` when `scope=current` and a current element exists, else
  `project` (the page hides its scope control then, `ux-reference.md` §4.8; TQ-2 (c), decided by
  the approver 2026-11-03). With
  `current`, `linked` holds the in-scope linked elements only and a reference with none is
  omitted; with `project`, every non-archived linked element.
- **references** — every reference with a category (TQ-1 (b), decided by the approver
  2026-11-03; the completion figures stay on `requirement` and `feature`), the element
  references and the pattern references alike; with `project`, also each non-archived element
  whose type's category is `requirement` or `feature` that no element references (`linked: []`,
  `status: "no-elements"`, `element: true`). A **pattern reference carries its id only** (RP3-14
  D9): no title, description or source. Ordered by natural id order; `linked` the same.
  `done`/`total` over `linked`; `percent` as §3, `null` when `total` is 0; `status`: `completed`
  (`done = total > 0`), `in-progress` (`0 < done < total`), `not-started` (`done = 0 < total`),
  `no-elements` (`total = 0`) — the four filters of R-01.3.
- **figures** — `completion` as §3 on `applied` (R-01.1: "Project completion 25 %");
  `coverage` (spec-005 §4, project-wide in both scopes): `total` = non-archived readable elements
  whose type has `requires`, `carrying` = those with a reference of every required category,
  `percent` as §3 ("Reference coverage 3/5", R-01.1); `no-requires` when `taxonomy.requires` is
  empty. `referencesWithoutElements` = the `no-elements` rows (0 with `current`).
- **missing** — the elements of §5's flag (id and missing categories, in the order `requires`
  declares them), ordered by natural id order: the page's section "Elements missing required
  references" (`ux-reference.md` §4.8 v0.3). References that a document names and no element
  links are out of v0.3 (D9).
- **elements** — every element that `linked`, `missing` or an element reference's `id` names,
  once, in the `/elements` row shape, so the web reuses its rows: `descriptor` gives the tone of
  a chip and the "who must act" of the detail (spec-003 §4, §5 texts; R-01.2), `done` the
  descriptor kind `last` (so the web does not re-derive it), `inScope` the rule of §1.
  As on `/elements` (`server/src/http/project-routes.ts` `elements`): when the Memory events
  cannot be read the descriptors are computed without them (actors, `rejection` and `since`
  degrade, spec-003 §4) and `eventsError` says why; a failed `dna show` adds no field — the
  descriptors see no member, so member actors fall back to `tech-lead` with
  `author-not-in-team` (spec-003 §4), and the project header's `dnaError` (`GET /api/p/:pid`)
  reports the failure.
- **No `ui.yaml`** (`ui.status.source` `none` or `ignored`): the inferred values (spec-005 §3) have
  no pattern and no `requires`, so `references` holds element references only (`patterns:
  false`), `coverage` is `no-requires`, and `completion` is `no-reference-categories` (no
  inferred category is `requirement` or `feature`). An empty `references` then renders R-01.4's
  "No references found — declare taxonomy patterns in ui.yaml".

### 8. Caching, invalidation and cost

- **Per state.** The index (§1) and the bodies of §3–§5 are derived values of the snapshot view
  (`server/src/snapshot/snapshot.ts`): memoised per content key (`<CLI generation>:<HEAD>.<working-
  tree hash>:<user.email>`), shared by every caller, computed once — like the descriptors
  (spec-003 §8, `adr-001` D6). `ui.yaml` is a working-tree file, so its edits change the key
  (spec-004 §5 `X-Repo-State`, the content fingerprint of REQ-STATE-02).
- **Reuse across states (a contract).** The values of an element file are kept per
  `(path, blob id)` and reused by the next state's index when the file is **not** in that state's
  working-tree status and its blob at the new HEAD is the same — one `git ls-tree -r HEAD` over
  the Memory directories per new HEAD (a git read, no CLI process). A file that is changed or
  untracked is read again on every state (the hash-only reads of spec-001 §4.4 serve the state key
  only and are not reused here). An entry is stored under a blob id only when its file was clean
  (not in the working-tree status) at read time; the values read from a modified file serve that
  state only, so a reverted edit never brings back the edited values. So a commit touching one element re-reads one file, and the
  index stays within REQ-PERF-03 on the `large` fixture (§11). Entries of paths `memory search`
  no longer lists are dropped.
- **Invalidation.** No new event: any change of the state emits `repo {pid, state}` (spec-004
  §6), on which the page refetches every query of that project — `/progress`, `/traceability`,
  `/elements` (TanStack Query invalidation, `adr-002`). That meets T-12.3, M-03.2 and T-08.2
  ("within 5 seconds", REQ-PERF-03). Every answer carries `X-Repo-State`.
- **CLI processes.** Opening Today with the progress card on a cold cache adds 0 CLI processes to
  the ≤ 6 of REQ-PERF-05 (`memory search` and `dna show` are Today's already); reopening any
  view with no change starts 0. Traceability on a cold cache: the same commands, each at most
  once per state. No archived list is read for these routes (TQ-3).
- **Index on every state with a `when-references-done` hold.** With such a hold in the
  effective `holds` (the sw-life-cycle preset's `release-line`, spec-005 §5) the descriptor needs
  the index, so Today and `/elements` build it on every state, not only the project-state views
  (§1 Cost); the reuse above keeps that to the changed files.
- **Time.** The routes answer within Today's and the other views' budgets: REQ-PERF-01 p95 ≤ 2.0 s
  warm for Today; REQ-PERF-04 p95 ≤ 1.0 s warm for the Memory list and, since TQ-6 (a) (decided by
  the approver 2026-11-03), for Traceability (US-R-01); REQ-PERF-03 5 s from a change to the
  updated figures. One index costs one file read per changed element and one pass over the kept
  values (at most 200 per element).

### 9. Sanitising and security

- **Repository text in the answers (K1).** Every display string a body takes from the
  repository passes through the character escape of the tool-message sanitiser (`neutralise`,
  `server/src/git/redact.ts`: CR LF folded, a backslash doubled, Cc/Cf/Cs/Zl/Zp but newline and
  tab escaped — no bidi control or invisible character reaches the page): element **titles**
  (the `/elements` rows here and everywhere, `ElementRef.title`, `scope.current`, the candidate
  titles of spec-011 §3), every **pattern reference** id (in `references[]` and
  `completion.references[]`; at most 256 characters as written, §1 rule 2; two values equal after
  the escape are one reference) and the **`ui.yaml` strings echoed** by `/config` `ui`
  (`patterns[].match`, type names, `phases`, `holds` types and states, `artifacts` paths). The
  rule is spec-004 §5's (amended with this spec); it lands with bug-027's task (the same class:
  repository text that reached the page unescaped). Element ids, types and states of `memory
  search` stay as returned: they are the keys the web sends back to the API (an element
  reference's `id` is such an id); the web renders them as text, never as HTML. The `ui.yaml`
  `failure` passes through the whole sanitiser (§2). Descriptor texts follow spec-004 §5 (D13).
- **No path, regex or command from input.** The only request input is `:pid` (an opaque id,
  REQ-SEC-04) and `scope` (an enum); filters and search are the web's, over the answer, by
  substring. The only regular expressions compiled are `taxonomy.patterns`, inside spec-005 §1's
  safe subset, tested on values of at most 256 characters; reference values are compared as
  strings and never become a path — an element file is read only at the path `memory search`
  returned (spec-001 §4.2), confined to the project.
- **Links.** Every link the web builds from these answers is an element address
  `/p/<pid>/e/<full id>` with `encodeURIComponent` (spec-011 §2); a pattern reference is never a
  link (D9).
- **Access.** Both routes are reads: the Host/Origin, `Sec-Fetch-Site` and session checks of
  spec-004 §1–§2; no identity is required (Casey reads them, US-T-12, US-R-01).
