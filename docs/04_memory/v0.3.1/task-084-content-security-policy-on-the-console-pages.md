## Description

The fix of bug-039: the console serves its pages with no `Content-Security-Policy` header (no
match in `server/src`; the only hardening header is `x-content-type-options: nosniff` on the event
stream, `server/src/http/events.ts`). Item 1 of `patch-v0.3.1` (decision N-001;
`dl-021-scope-and-order-of-the-releases-from-v0.3.1-to-v0.4.1` Decision 3).

**Backlog items:** GOV (governance — the fix of bug-039)

## Acceptance Criteria

- **AC-1 — The header on every page response.** Every HTML response of the console carries a
  `Content-Security-Policy` header: scripts, styles, fonts and connections from the console's own
  origin only; the inline theme script (`web/index.html`, `<script id="wfui-theme">`) allowed by
  its hash, not by `'unsafe-inline'` for scripts; React Aria's inline `style` allowed as the design
  decides (`'unsafe-inline'` for styles or nonces, the choice recorded); no `object`, no frame, no
  remote image (bug-039 *Suggested fix*). A server test asserts the header on each page route (red
  before the fix).
- **AC-2 — The console works with it in force.** No CSP violation in the browser console on any
  screen, and the e2e suite passes on Chromium, Firefox and WebKit with the header in force (`npm
  run test:e2e`, on `gates.yml`); 0 serious/critical axe violations unchanged.
- **AC-3 — The spec and the docs.** spec-004's response headers gain the policy as a dated *Process
  Note* (§1 / §5, the spec has no header list today); `CHANGELOG.md` *[0.3.1]* names the fix; the
  touched documents' Version/Date bumped.
