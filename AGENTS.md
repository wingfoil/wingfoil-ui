# WingFoil UI

This project is governed by WingFoil. Its configuration is in `.wingfoil/`; its decisions, tasks
and plans are its Memory.

- **Approvals are the approver's.** An agent never approves or rejects: it hands the approver the
  exact command to run.
- **Memory changes only through the WingFoil CLI** (`memory add`, `memory submit`, `memory park`,
  …; `memory approve` is the approver's), never by editing an element's state by hand.
- **Which workflow to start:**
  - a decision that changes no governance: `decision-log-ingest`;
  - a change of the project's governance (its `.wingfoil/`, this file, the roles, the Memory
    types): `governance-evolution`;
  - a retrospective: `retrospective-periodic`, which runs `retrospective`.
- Read the directives that apply to the role you act in before you change anything.

## The software life cycle

This project runs `sw-life-cycle`: inception, specification, delivery and end of life. Each of
these is a slot: its workflow is a phase pack's or `software`'s default, and `delivery` is the
methodology's. `delivery` creates the releases and runs `release` over each one: `submit` (the
checks, `releasing`, the approval), then `publishing` (commit, rehearsal, tag, publication,
`released`).

- **Which workflow to start:**
  - an architecture decision: `adr-ingest`;
  - a bug found: `bug-ingest`.
- **AI agent (Claude/Cursor/etc.) acts as developer, reviewer, qa and architect**, and never approves: it hands
  the approver the exact command. A `bug` at `triaged` or `planned`, including one parked back to
  `planned`, moves only by the approver's `approve`.
- **End of life:** `announce` passes `--tags end-of-life` to `memory add`, since `approve` selects
  the announcement by that tag.

## Scrum

This project runs Scrum (the Scrum Guide, November 2020) as the `delivery` of its life cycle.

- **Sprints of 2 weeks, one at a time.** `delivery` runs each Sprint: planning, its
  Sprint Backlog (the tasks whose `sprint` names it) through `backlog-item`, its releases, the
  review, the retrospective, then `close`.
- **Roles:** the Product Owner is `product-owner`, the Scrum Master `facilitator`, the Developers
  `developer` with `architect`, `reviewer`, `qa` and `tech-lead`.
- **Definition of Done:** an item is done only when the `definition-of-done` directive holds.
- **Releases** are decoupled from the Sprint boundary and gated by no review, but a release of a
  Sprint is approved and published only once its Sprint Backlog is done or moved.
- **AI agent (Claude/Cursor/etc.)** works for the Developers, as their tool, holds no Scrum accountability and
  never approves: it hands the approver the exact command.

- **A `bug` at `planned`** (including one parked back to `planned`) moves to `in-progress` with

- **One exception** to "Memory changes only through the WingFoil CLI": a phase plan is closed by a

  WingFoil 0.3.1 accepts a hand-committed `status:` without the approver, so never write one.
- **`memory deprecate`** needs no approval in WingFoil 0.3.1 (any git identity, member or not, can
  run it on any element): run it only in `end-of-life` › `deprecate`, or with the approver's OK
  recorded in the active plan — never on your own (directive `wingfoil-cli`).
